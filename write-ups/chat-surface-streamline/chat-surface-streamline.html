Rebuilding the chat surface, one measured rung at a time

The AI chat component had blown the render budget for smooth morphing. Instead of patching the old surface, we built a complete alternative next to it — starting from a skeleton that had to beat the old surface before it earned its first feature, then climbing a ladder where every rung re-ran the same performance gate. Eight steps later, the new surface is the default and the old one is one click away.

2 · The decision: build up, not patch down

“Create a complete alternative of the current AI chat component (which can be used as reference) and measure render performance from a base implementation and gradually add features while maintaining a performance budget.” — the brief, verbatim

That one sentence set the whole shape of the night:

  • A 3-way switch (fake / reference / next) so both surfaces run side by side, flippable from the debug sidebar or an RPC — every measurement is a paired A/B, not a guess.
  • The old surface becomes the spec. Its capability surface is the feature checklist; its measurements are the bar to beat.
  • The budget is a gate, not a report. A standing table of pass/fail numbers, re-run at every rung. A step that regressed it would not ship.
  • The diagnosis became a “do-not-inherit” list: no per-frame width feeds, no ViewThatFits ladders, no monolith body, no scroll-per-token.

Two more requirements joined before the first commit: the surface must be mode-aware (compact in a tall narrow deck card; a centred readable column — not edge-to-edge — on a wide focus surface), and streaming is the design centre: the transcript mutates many times a second while the user may simultaneously be morphing or scrolling.

3 · The ladder

The standing budget — re-run at every rung

Morph & step scenarios: ≥ 55 fps, worst frame ≤ 34 ms, main-thread stalls ≤ 50 ms over the fake floor (the floor itself moves with machine load, so stall verdicts are floor-relative). Step-settle re-entry ≤ 100 ms warm. Streaming at rest: 60 fps with zero settled-row evals per token and parse cost O(tail). A step that regresses any of these does not ship. Full table: 337.04-BUDGETS.md.

Skeleton

Plain-text transcript for all four agent families. Width is measured once and latched — frozen during motion, so a morphing frame moves a constant-width column instead of re-wrapping text. Centred 720 pt column in focus; compact density in decks — both as values, never view structure.

Commentary: two incidents. 4 · The mechanism that killed the big stall

The canvas used to destroy a chat deck's hosting view the moment the deck left the live set. The new surface made first render cheaper, but only parking makes re-entry cheap: the host is retained in a small LRU tier and the same instance is re-attached on return.
