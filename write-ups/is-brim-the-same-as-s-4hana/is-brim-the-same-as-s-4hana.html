Is BRIM the same as S/4HANA?

No — and they aren't nested either. One names a solution, the other names a system, and the modelled tables sit in the overlap.

The three labels

Each modelled table carries three different kinds of name, and they answer three different questions.

  • Solution — which BRIM component owns it. Answers: what business capability is this?
  • System — S/4HANA, for all twelve. Answers: where does the data physically live?
  • Business entity label — the human name in the mapping sheet, paired with the technical SAP table name. Answers: what does a reader call this?

How we know it's S/4HANA, not older ECC

Two things in the model itself settle it, rather than an assumption:

  • The custom fields follow the ZZ1_<name>_<context> pattern — that is S/4HANA key-user extensibility specifically, from the Custom Fields & Logic app.
  • DFKKOP declares cds_view_name: I_CADOCUMENTBPITEMLOGICAL, an S/4HANA CDS interface view.

What this exposes in the model

The datastore field disagrees with itself: ten entities say SAP_HANA, but 1FE_0ZAP14IT00 and DFKKINVDOC_H say SAP_BRIM. Those aren't two spellings of one thing — one is a database, the other a solution portfolio — and the split follows no pattern. It came in from the upstream 00T YAML.

schema has a similar split, but that one is informative: SAP_BP for the three master-data tables, SAP_BRIM for the other nine — which matches the diagram exactly.
